# 代码讲解：逐行、绝对路径、不用模糊代词

## 0. 一句话

讲代码不是“贴一段 + 讲大意”，是**每一行都能对上它的作用、位置和意图**；提到文件给绝对路径；指代用名字或行号，不用模糊代词。

## 1. 逐行说明

### 1.1 硬规则

- 任何代码讲解，代码块之后必须**逐行说明**：不漏行、不跳行。
- 每条说明以**行号**开头，并引用该行的关键片段；这样代码块保持可复制，也能对上。
- 空行、单独的括号、纯闭合符号：可以合并说明，但要写明合并了哪些行、为什么（“第 6–7 行是缩进收尾，无逻辑”）。
- 重复样板（连续 import、装饰器、类型声明）：可以按行号范围合并，但必须明确范围，不能默认“显然”。
- 长代码（>50 行）：先给结构图，再按函数/代码块逐段逐行；不要因为长就只讲大意。
- 用户明确说“只讲整体，不要逐行”：尊重；先确认一次，之后给整体 + 关键行。

### 1.2 每行讲什么

按需讲三件事，不必每行都写满：

1. **做了什么**：效果，不是字面翻译。
2. **为什么在这**：意图、约束、依赖。
3. **改了会怎样**：边界、风险、替代写法（可选）。

### 1.3 讲意图，不逐字翻译

- `i++` 不是“i 加加”，是“计数器加一”。
- `return` 不是“返回”，是“把结果交回给调用者，函数到此结束”。
- `try/except` 不是“尝试/除了”，是“先执行 try 块；抛异常时跳到对应的 except”。
- 一行只做一件事时，一句话就够；不要把一行写成一段论文。

### 1.4 标准格式

代码块保持干净，说明用编号列表：

````markdown
`D:\work\demo\main.py`：

```python
def add(a, b):
    return a + b
```

- 第 1 行：`def add(a, b):` —— 定义函数 `add`，接收两个参数 `a`、`b`；函数体在下一行。
- 第 2 行：`return a + b` —— 把 `a + b` 的结果交回给调用方；这一行同时结束函数。
````

长代码分块时，每块前给行号范围：

> `D:\work\demo\pipeline.py` 第 12–35 行，`load_config` 函数：

然后逐行说明。

## 2. 文件用绝对路径

- 讲解里提到文件，给**绝对路径**：
  - Windows：`D:\work\project\src\main.py`
  - POSIX：`/home/me/project/src/main.py`
- 不用 `./src/main.py`、`src/main.py`、`main.py` 这类相对路径或裸文件名。
- 不确定绝对路径：直接说“我不知道这个文件的绝对路径”，并给获取方式；**不猜**。
- 示例路径要标注“示例路径”，不要伪装成真实文件。
- 同一文件重复提到：第一次给绝对路径并定义简称（`D:\work\project\src\main.py`，下称 `main.py`），之后可以用简称；简称必须明确、唯一。
- 文件在 URL 上：给完整 URL，不用“那个链接”。

## 3. 不用模糊代词

### 3.1 禁止的是什么

指代对象需要读者猜的代词：

- “这个函数会重试。”——哪个函数？
- “它失败时抛异常。”——它是谁？
- “这里把计数加一。”——哪一行？
- “上面的变量没初始化。”——哪个变量？
- “前者比后者快。”——哪两个？

### 3.2 改成什么

- “这个函数” → “`retry` 函数”
- “它返回” → “`retry` 返回”
- “这里” → “第 7 行”
- “上面的变量” → “第 3 行的 `retry_count`”
- “前者/后者” → 直接写两个名字

### 3.3 允许的代词

指代对象紧挨着、不会歧义时，可以用：

> `retry_count` 是已重试次数；它在第 12 行被重置为 0。

“它”指 `retry_count`，清楚。**禁止的是“读者要猜”的代词，不是所有代词。**

不要为了避开代词把句子写僵：用名字和行号，不用“该对象 / 上述实体”堆砌。

## 4. 失败模式

- 贴一大段代码，只讲“整体逻辑”，不逐行。
- 逐行变成逐字翻译：`i++` 说成“i 加加”，不讲意图和效果。
- 漏行、跳行不说明，或说“这几行显然”。
- 只讲关键行，其他行默认读者能懂。
- 文件用相对路径、裸文件名，或猜一个绝对路径。
- 用“这个 / 它 / 这里 / 上面”指代不明。
- 用“上面 / 下面”代替行号或名字。
- 为避代词把句子写得拗口。
- 代码块没有行号，正文却说“第 3 行”，对不上。
- 用户说“只讲整体”，还强行逐行。

## 5. 和教学循环的关系

- 代码是实践材料：先让他预测/改一行/跑一下，再逐行讲；不要先逐行讲完再让他动手（符合 4.1）。
- 逐行讲解是“命名”的一部分：把直觉变成可指认的结构。
- 代码里的术语/缩写（API、RTT、PSK、401、`try/except`）第一次出现也要按 `references/terminology.md` 解释并确认。
- 讲完给一个“改一行会怎样”的再用，而不是停在“看懂”。

## 7. 正反例

**坏**：

> 这个函数就是重试，失败了就抛异常。文件在 utils.py。

**好**：

> `D:\work\project\src\utils.py`，第 3–10 行：
>
> ```python
> def retry(fn, n=3):
>     for i in range(n):
>         try:
>             return fn()
>         except Exception:
>             if i == n - 1:
>                 raise
> ```
>
> - 第 3 行：`def retry(fn, n=3):` —— 定义 `retry`，接收一个无参函数 `fn` 和重试次数 `n`（默认 3）。
> - 第 4 行：`for i in range(n):` —— 最多循环 `n` 次，`i` 是当前第几次（从 0 开始）。
> - 第 5 行：`try:` —— 开始一个可能抛异常的块。
> - 第 6 行：`return fn()` —— 调用 `fn()`；成功就立刻返回，后面的重试不再执行。
> - 第 7 行：`except Exception:` —— 捕获 `fn()` 抛出的异常，进入重试逻辑。
> - 第 8 行：`if i == n - 1:` —— 判断是不是最后一次重试。
> - 第 9 行：`raise` —— 最后一次仍失败，重新抛出异常，交给调用方。

## 8. 一句话

> 每一行都能指出来，每一个文件都有全路径，每一个“它”都有名字。
