# 术语：先解释，确认后再默认使用

## 0. 一句话

任何术语、缩写、英文缩写、黑话，第一次出现都要解释；**确认用户知道之后，才能默认用简称**。

## 1. 什么算“术语”

- **领域术语**：极限、幂等、协方差、梯度。
- **缩写 / 首字母**：RTT、PSK、API、LLM、CRUD。
- **英文缩写 / 全称**：QUIC、TCP、TLS、HTTP。
- **团队黑话 / 内部说法**：灰度、埋点、打平、对齐、闭环。
- **特殊记号**：ε-δ、O(n)、∇、∂。
- **他可能不熟的日常词**：按“他可能不熟”判断，不按“我觉得简单”判断。

## 2. 第一次出现的格式

```
X（全称 / 英文全称；白话：一句话说它是什么、干什么；例子：一个具体场景）
```

- 不要只给全称，不给作用。
- 例子可选，但推荐；没有例子时，白话必须能独立站住。
- 一次不要超过 3 个新词；超过就分批。

## 3. 确认：关键一步

解释之后，确认他懂，再默认用简称：

- **单词**：
  > “`X` 这个词你之前接触过吗？熟我就直接用 `X`，不熟我再展开。”
- **批量**：
  > “接下来会用到 3 个词：`A`、`B`、`C`。各一句解释；哪个不熟点哪个。”
- 他答“知道 / 见过 / 不用解释” → 记为已知，可用简称。
- 他答“不知道 / 展开” → 展开；等他确认或正确使用后，再用简称。
- **他没回答** → 本轮继续用全称 / 白话，不默认简称；下一轮再确认。
- 他**正确使用**该词 → 视为已知证据，可默认。
- **不要把“没反驳”当“懂了”。**

## 4. 记录

- 用 CLI 记录：
  ```bash
  glossary --add --term X --full "全称" --plain "白话" --example "例子" --consent outline
  ```
- 下次开工先读 `learner/glossary.md`；已解释过的，可以先用简称，但仍可一句“`X`（上次说过）”。
- **已解释 ≠ 已确认**：没确认过的，下次仍先解释/确认一次。

## 5. 反模式

- 一上来：“QUIC 的 0-RTT 用 PSK，配合 TLS 1.3 省一个 RTT。”
- 只给全称，不讲作用。
- 解释完立刻用简称，不确认。
- 一次抛 5 个缩写，用户不知道从哪问起。
- 用英文缩写装专业。
- 把“显然 / 众所周知”当解释。
- 过度解释日常词（函数、变量、文件），拖慢对话。
- 把“用户没问”当“用户懂”。

## 6. 正反例

**坏**：

> 这个 API 用 JWT 做鉴权，失败会返回 401。

**好**：

> 这里会出现三个词：
> - **API**（Application Programming Interface）：程序之间互相调用的接口。
> - **JWT**（JSON Web Token）：一种带签名的令牌，服务端用它认人。
> - **401**：HTTP 的“未认证”状态码，意思是“你没带有效凭证”。
>
> 这三个词你之前接触过吗？熟我就直接用，不熟我逐个展开。

## 7. 和代码讲解的关系

代码里的缩写/术语也适用：库名、协议名、状态码、配置项，第一次出现先解释再默认使用。逐行说明里也不要默认用户懂 `try/except`、`PSK`、`RTT` 这类词。

## 8. 一句话

> 第一次出现，解释；确认他懂，再用简称。
